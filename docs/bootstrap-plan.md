# Bootstrap plan

Goal: demonstrate a reliable small local work loop before spending on visual production or multiplying agents.

## Stage 0: make the operating model inspectable

Deliver the glossary, permission model, coordination contracts, research sources, launch briefs, report templates, and CPU-only experiment catalog. Run mechanical documentation checks and request fresh-context review. The documentation branch is a proposed foundation, not an operational swarm.

## Stage 1: preflight, then two disjoint research lanes

**DF-PREFLIGHT-01** inspects the actual local environment without installing or launching anything. The report distinguishes observed capabilities, documentation claims, and unknowns. Stop when the report and recommended smallest next probe are ready.

After that report, launch at most two disjoint sessions:

- **DF-RESEARCH-01** compares an explicit CLI adapter, SDK adapter, and adopting/adapting Symphony. Deliver a source-backed recommendation and a smallest live probe; no installation or nested model calls.
- **DF-PROTOCOL-01** challenges the proposed coordination contracts with failure traces and designs a deterministic fake-worker harness. Deliver examples and acceptance tests as a plan, not a daemon.

Their outputs are separate reports. Neither edits the other's files, shared operating policy, or main. The orchestrator integrates recommendations on a new planning revision. **DF-VERIFY-01** then independently checks that revision and its launchability. This is a sequence with limited parallelism, not four permanently running agents.

## Stage 2: offline controller semantics

Commission one builder to implement only the fake-worker harness after its proposal is reviewed. Use temporary files, deterministic fixtures, a fake clock, and no provider calls. Exercise duplicate delivery, stale ownership, restart, cancellation, digest mismatch, missing evidence, and allowance accounting.

Exit: every mandatory failure case in [the precursor suite](experiments/precursor-suite.md) has reproducible positive and negative tests; a fresh reviewer re-runs them. This establishes simulation behavior, not live Codex or GitHub integration.

## Stage 3: one live bounded loop

With explicit permission, run one simple documentation Work Order through the chosen installed Codex transport, capture real identity/events/output, and route a frozen Submission to one fresh reviewer. Test stop/resume behavior on disposable work. No automatic merges.

Exit: the exact real entry point works, final state and usage are recorded honestly, and review has no critical FAIL or BLOCKED. A missing live capability blocks this stage rather than being replaced with mocked evidence.

## Stage 4: three-slot research prototype

Use two producer slots and one review slot, with no GPU or rendering. A steward may be a controller policy or a temporary assignment; it need not be a fourth persistent model session. Run a human-approved bounded batch, checkpoint results, and stop.

Exit: no duplicate active ownership, every accepted submission has a matching independent Assessment, cancellation/recovery works, and the human is not manually relaying routine intermediate messages. That last condition requires a real controller/bridge and is not met by merely posting launch briefs.

## Stage 5: tune before expanding

Compare serial work, independent parallel work, and coordinated parallel work on the same small corpus. Measure correctness, independently accepted outputs, useful decisions, user interventions, elapsed time, total reported model usage, and failures. Freeze rubric and task set for the comparison.

Increase one of concurrency, unattended duration, task breadth, or authority at a time. Predefine the criterion for retaining a change. A higher agent count or rising self-score is not evidence of improvement. Retain a rollback point and the prior policy.

Creative rendering returns only as a separate, explicitly authorized Campaign after the research loop works. The original Dream Loop/anidoodle destination remains intact; it is not a requirement for Stage 1.
